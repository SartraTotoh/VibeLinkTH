## 0. เตรียมเครื่องก่อนทดสอบ

เปิด Terminal ที่โฟลเดอร์โปรเจกต์ แล้วรัน:

```powershell
npm run dev -- -p 3010
```

เปิดเบราว์เซอร์ที่:

```text
http://127.0.0.1:3010/qr
```

หมายเหตุ:

- ใช้พอร์ต 3010 ตามที่ทดสอบในรอบนี้ (ถ้าพอร์ตไม่ว่าง ให้เปลี่ยนเลขและจดไว้)
- ต้องเป็น Dev Server ในเครื่องเท่านั้น ห้ามชี้ไป Production
- QR ที่สร้างจะฝัง **URL ปลายทาง** ไม่ได้ฝังที่อยู่ Dev Server
- ถ้าจะสแกนด้วยมือถือ ให้ใช้ URL สาธารณะ เช่น `https://example.com/demo` — **ห้ามใช้ `http://127.0.0.1` หรือ `localhost` เป็นปลายทาง** เพราะมือถือจะเปิดไม่ได้
- ถ้าต้องการเปิดหน้า `/qr` บนมือถือจริง ให้ใช้ IP ในวง LAN เช่น `http://192.168.x.x:3010/qr` และต้องอยู่ใน Wi-Fi เดียวกัน (อย่าเปิดพอร์ตออกอินเทอร์เน็ต)
- เปิด DevTools Console ไว้และตรวจว่าไม่มี error สีแดงระหว่างทดสอบ

### URL ทดสอบที่ปลอดภัย

ใช้เพียง URL ตัวอย่างเหล่านี้:

- `https://example.com/demo`
- `https://www.iana.org/help/example-domains`

ห้ามใช้ URL ที่มี `token=`, `password=`, `key=`, `session=`, อีเมลลูกค้า หรือลิงก์แดชบอร์ดภายใน

## 1. เปิด `/qr`

**ขั้นตอน**

1. เปิด `http://127.0.0.1:3010/qr`
2. ตรวจว่าหน้าโหลดได้โดยไม่ต้องล็อกอิน
3. ดูว่าเห็นหัวเรื่อง `QR STUDIO`, ขั้น `01 ปลายทาง`, `02 ดีไซน์`, `03 เช็กก่อนโหลด` และแผง `พรีวิว` / `ดาวน์โหลด`
4. เปิด Console ดูว่ามี error หรือไม่

**ผลที่ต้องได้**

- หน้าโหลดได้ ไม่เด้งไปหน้าอื่น
- ช่อง `ลิงก์ปลายทาง` ใช้งานได้
- ปุ่มดาวน์โหลดยังล็อกอยู่ตอนที่ยังไม่มี URL
- ไม่มี error ใน Console

**ผลจริง:** ☐ ผ่าน ☐ ไม่ผ่าน — หมายเหตุ: ______________________

## 2. สร้าง QR จาก URL สั้น

**ขั้นตอน**

1. ใส่ `https://example.com/demo` ในช่อง `ลิงก์ปลายทาง`
2. รอประมาณ 1–3 วินาที
3. ดูแผง `เช็กก่อนโหลด` และ `พรีวิว`

**ผลที่ต้องได้**

- เห็น QR บนพรีวิว
- มีข้อความ `Decode สำเร็จ`
- มีข้อความ `พร้อมดาวน์โหลด`
- รายการ Scan Health ครบ 10 ข้อ และไม่มีข้อใดสถานะ `ไม่ผ่าน`
- ปุ่ม `PNG` และ `SVG` ใช้งานได้

## 3. ดาวน์โหลด PNG

**ขั้นตอน**

1. เลือกขนาด `1024px` (ค่าเริ่มต้น)
2. กดปุ่ม `PNG`
3. เปิดไฟล์ที่ดาวน์โหลด
4. ตรวจชื่อไฟล์และภาพ

**ผลที่ต้องได้**

- ได้ไฟล์ชื่อประมาณ `vibelink-qr-example.com-YYYYMMDD.png`
- ภาพคม ไม่แตก ไม่มีแถบสีหรือพื้นหลังแปลก
- ขอบ QR (quiet zone) มีที่ว่างรอบด้าน
- เปิดภาพบนจอแล้วเห็น QR ชัดเจน

**ผลจริง:** ☐ ผ่าน ☐ ไม่ผ่าน — หมายเหตุ: ______________________

## 4. ดาวน์โหลด SVG

**ขั้นตอน**

1. กดปุ่ม `SVG`
2. เปิดไฟล์ `.svg` ด้วยเบราว์เซอร์หรือโปรแกรมดูภาพที่เชื่อถือได้
3. ตรวจว่าเปิดได้และเห็น QR

**ผลที่ต้องได้**

- ได้ไฟล์ชื่อประมาณ `vibelink-qr-example.com-YYYYMMDD.svg`
- เปิดได้ ไม่ขึ้น XML error
- ไม่มี `<script>` และไม่มีลิงก์ภายนอกในไฟล์
- ภาพ QR เหมือนพรีวิว

**หมายเหตุสำหรับมือถือ**

- Android: เปิด SVG ใน Chrome/Files ได้ แล้วใช้มือถืออีกเครื่องสแกน
- iPhone: บันทึกลง Files แล้วเปิดด้วย Safari หรือใช้เครื่องคอมพิวเตอร์เปิด SVG บนจอ
- **ห้ามอัปโหลด SVG ขึ้นเว็บแปลงไฟล์ออนไลน์** เพราะอาจมี URL ปลายทางติดไปด้วย

**ผลจริง:** ☐ ผ่าน ☐ ไม่ผ่าน — หมายเหตุ: ______________________

## 5. สแกนด้วยกล้องโทรศัพท์จริง

**ขั้นตอน**

1. เปิดไฟล์ PNG จากข้อ 3 บนจอคอมพิวเตอร์ (ขนาดอย่างน้อย 5 ซม.)
2. ใช้กล้องหลังของโทรศัพท์สแกน โดยถือห่างประมาณ 15–30 ซม.
3. ตรวจว่าเบราว์เซอร์เปิด URL ตรงกับ `https://example.com/demo`
4. ทำซ้ำกับไฟล์ SVG จากข้อ 4

**ผลที่ต้องได้**

- กล้องอ่าน QR ได้ทั้ง PNG และ SVG
- ปลายทางที่เปิดคือ `https://example.com/demo` ตรงทุกตัวอักษร
- ไม่มีข้อความแปลกปลอมหรือ URL อื่น

**ถ้าไม่ผ่าน**

- จดว่าล้มเหลวจาก PNG หรือ SVG
- จดยี่ห้อ/รุ่นโทรศัพท์และแอปกล้อง (ไม่ต้องใส่ข้อมูลส่วนตัวอื่น)
- ถ่ายภาพหน้าจอเฉพาะ QR ที่ใช้ URL ตัวอย่างเท่านั้น

**ผลจริง:** ☐ ผ่าน ☐ ไม่ผ่าน — PNG: ______ SVG: ______ หมายเหตุ: ______________________

## 6. ทดสอบ Blink, Pank และ Print Safe

**ขั้นตอน**

1. ใส่ URL `https://example.com/demo` อีกครั้ง
2. เลือกธีม `Blink` → รอ `Decode สำเร็จ` → ดาวน์โหลด PNG
3. เลือกธีม `Pank` → รอ `Decode สำเร็จ` → ดาวน์โหลด PNG
4. เลือกธีม `Print Safe` → รอ `Decode สำเร็จ` → ดาวน์โหลด PNG
5. สแกนทั้ง 3 ไฟล์ด้วยกล้องโทรศัพท์

**ผลที่ต้องได้**

- ทั้ง 3 ธีมมีข้อความ `Decode สำเร็จ` และ `พร้อมดาวน์โหลด`
- สแกนได้ทั้ง 3 ไฟล์
- สีของแต่ละธีมต่างกันชัดเจน
- Print Safe เป็นดำบนขาว

**ผลจริง:** ☐ ผ่าน ☐ ไม่ผ่าน — Blink: ______ Pank: ______ Print Safe: ______

## 7. ทดสอบ Logo และ Frame

**ขั้นตอน**

1. ใช้ URL `https://example.com/demo`
2. กดปุ่มใส่โลโก้ แล้วเลือกไฟล์ PNG ขนาดไม่เกิน 512KB และไม่เกิน 1024px
3. ตรวจว่าโลโก้อยู่กลาง QR และขนาดเริ่มต้นไม่เกิน 14%
4. เลือก Frame เป็น `Caption` หรือ `Ticket`
5. ใส่ CTA เช่น `Scan to Book` (ไม่เกิน 48 ตัวอักษร)
6. รอ `Decode สำเร็จ` แล้วดาวน์โหลด PNG
7. สแกนด้วยโทรศัพท์

**ผลที่ต้องได้**

- โลโก้แสดงกลาง QR และไม่ทับตำแหน่งมุมทั้งสาม
- Health ยังไม่มีข้อ `ไม่ผ่าน`
- CTA อยู่ใต้ QR ไม่ทับโมดูล
- สแกนได้และปลายทางถูกต้อง
- ถ้าลองอัปโหลดไฟล์ SVG เป็นโลโก้ ระบบต้องปฏิเสธและแจ้งว่าให้ใช้ PNG

## 8. ทดสอบ URL ที่มี UTM

**ขั้นตอน**

1. ใส่ URL `https://example.com/demo`
2. กดปุ่ม `UTM`
3. กรอก:
   - Source: `phone-test`
   - Medium: `manual`
   - Campaign: `prompt-a`
4. รอ `Decode สำเร็จ` แล้วดาวน์โหลด PNG
5. สแกนด้วยโทรศัพท์ แล้วดู URL ในแถบที่อยู่

**ผลที่ต้องได้**

- URL ที่เปิดมี `utm_source=phone-test`, `utm_medium=manual`, `utm_campaign=prompt-a` และ `ref=vibelink`
- ค่าเดิมของ URL ไม่หาย
- สแกนได้

**ข้อห้าม**

- ห้ามใช้ URL แคมเปญจริงที่ผูกกับบัญชีโฆษณา
- ห้ามใส่ข้อมูลส่วนตัวในค่า UTM

## 9. ทดสอบ QR ที่แสดงบน Desktop และ Mobile

**ขั้นตอน**

1. Desktop: เปิด `/qr` ที่ความกว้างหน้าต่างประมาณ 1440px
2. Mobile: เปิดด้วยโทรศัพท์ผ่าน Wi-Fi เดียวกันที่ `http://<LAN-IP>:3010/qr` หรือใช้ DevTools โหมดอุปกรณ์ 390×844
3. ตรวจลำดับและขนาดของแต่ละส่วน

**ผลที่ต้องได้**

- Desktop: ขั้น 01 → 02 → 03 อยู่คอลัมน์ซ้าย และพรีวิว/ดาวน์โหลดอยู่ด้านขวา
- Mobile: ลำดับเป็น 01 → 02 → 03 → พรีวิว → ดาวน์โหลด
- ไม่มี horizontal scroll
- ปุ่มกลุ่มเดียวกันกว้างเท่ากันและชิดขอบการ์ด
- หัวเรื่องไม่ถูกตัด และข้อความไม่ล้นปุ่ม
- ไม่มีเส้นขอบสี (ดูเป็นพื้นไล่สี/เงาแทน)
- กดปุ่มด้วยนิ้วได้ ไม่มีปุ่มซ้อนกัน

**ผลจริง:** ☐ ผ่าน ☐ ไม่ผ่าน — Desktop: ______ Mobile: ______ หมายเหตุ: ______________________

## 10. พิมพ์จริงและสแกนอีกครั้ง (ถ้าทำได้)

**ขั้นตอน**

1. ใช้ธีม `Print Safe`
2. ตั้งขนาด QR ประมาณ 40–50 mm (หรือใช้ค่า `พิมพ์` ใน Scan Health)

4. ใช้กระดาษขาวธรรมดา
5. สแกนด้วยกล้องโทรศัพท์ในแสงปกติ ที่ระยะ 20–30 ซม.

**ผลที่ต้องได้**

- QR บนกระดาษคม ไม่แตก
- กล้องอ่านได้
- ปลายทางถูกต้อง
- ไม่มีขอบสีหรือแถบหมึกทับ quiet zone

## เงื่อนไขหยุดและรายงานทันที

หยุดทดสอบและแจ้งเจ้าของโปรเจกต์ทันที ถ้าพบข้อใดข้อหนึ่ง:

- ปุ่มดาวน์โหลดโหลดไฟล์เปล่า หรือไฟล์เสีย
- พิมพ์แล้ว QR ถูกตัด/เบลอจนสแกนไม่ได้
